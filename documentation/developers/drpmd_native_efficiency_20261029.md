## 测量定义

GitHub Ubuntu runner，AMD EPYC 7763，4 个可见逻辑 CPU；Python 3.12.15、NumPy 2.5.4、gfortran 13.3。FP64，无 fast-math；BLAS 单线程，`OMP_DYNAMIC=FALSE`，`OMP_WAIT_POLICY=PASSIVE`。

同一 HHOO Fortran PES、相同初态和时间步：0.05 fs × 1000 步，即每条 50 fs。每项重复 3 轮，报告墙钟时间中位数。准备初态的 200 步热化不计时，也不能当作热化收敛证据。

单轨迹基准比较 Python/C 时间循环，PES 两者均为原生 Fortran，故这里隔离的是传播层变化，不重复计入上轮从 NumPy PES 改成 Fortran 的收益。
多轨迹固定总工作量为 **8 条**，每条相同的 1000 步。暖态计时包括每条任务一次派发和最终 q/p 回传，不包括进程启动、文件输出或产物分类。原始 JSON 另存启动和冷启动首轮时间。

计算槽数 c = 并行轨迹进程数 × 每轨迹线程数。S(c)=T(1)/T(c)，E(c)=S(c)/c。逻辑计算槽不等于已确认的独立物理核心；此次没有获得足够的 CPU 拓扑/配额证据，不将 4 线程效率下降归因于某个已证实的硬件原因。

## 正确性与边界

原生回归覆盖 P=1/2/奇数/偶数、独立工作区、线程数变化、时间反演、不同 C 块长度、热化随机数尾部/时钟一致性、产物检查与输出步次、求力失败后的完整回滚、HHOO 1000 步和完整 driver。

本基准记录的所有最终 q/p 与对应参考结果逐元素相同（最大差 0）；这是这组样本与编译环境的结果，不承诺跨编译器/硬件逐位一致。能量归约仍可能因 NumPy/C 求和顺序有末位差异。

`native_block_steps=256` 仅是块上限；每次遇到 classifier 或输出事件会提前返回 Python，不改变实际检查频率。因此真实生产输出/判据越频繁，收益可能小于本报告的纯传播计时。

CUDA、多卡实际性能、MPI 跨节点、长时能量稳定性和收敛化学速率均不由本报告证明。参见 [原生使用指南](../users/drpmd_native.rst)。
